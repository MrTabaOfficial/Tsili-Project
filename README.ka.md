# Tsili

[English](README.md) · ქართული

[![CI](https://github.com/MrTabaOfficial/Tsili-Project/actions/workflows/ci.yml/badge.svg)](https://github.com/MrTabaOfficial/Tsili-Project/actions/workflows/ci.yml)

Tsili (წილი) საერთო ხარჯების გასაყოფი აპლიკაციაა მოგზაურობისთვის ან საერთო ბინისთვის. ყველა იწერს, რა გადაიხადა, აპი ითვლის, ვინ ვის რამდენი უნდა მისცეს, და გთავაზობს უმცირეს რაოდენობის გადახდებს, რომლებიც ყველაფერს ასწორებს. მუშაობს სრულად ოფლაინ და ტელეფონებს შორის სინქრონიზდება, როცა კავშირი არის.

## შესაძლებლობები

- **ჯგუფები** მოგზაურობისთვის ან ბინისთვის, წევრები ემატებიან სახელით. სხვები უერთდებიან რვასიმბოლოიანი მოსაწვევი კოდით ან მოსაწვევი ბმულით, რომელიც აპს შეერთების ეკრანზე შევსებული კოდით ხსნის.
- **ხარჯები**: ვინ გადაიხადა, თანხა, აღწერა და თარიღი. გაყოფის სამი წესი: თანაბრად, ზუსტი თანხებით ან წილებით (წყვილი 2, მარტოხელა 1).
- **ბალანსები** თითოეული წევრისთვის, ყოველ ჯერზე ჩანაწერებიდან გადათვლილი, და შემაჯამებელი ბარათი, რომელიც ერთი შეხედვით გეუბნება, გერგება თუ გმართებს.
- **ანგარიშსწორება** უმცირესი რაოდენობის გადახდებით, რომლებიც ყველა ბალანსს ასწორებს, და გადახდის ჩაწერა ერთი შეხებით, როცა ის მოხდება.
- **გადახდები** („ნინომ ლუკას 40 ლარი გადაუხადა“) ხარჯების გვერდით იწერება; ყველაფრის რედაქტირება და წაშლა მოგვიანებითაც შეიძლება.
- **ჯერ ოფლაინ.** ყველა ეკრანი სერვერის გარეშე მუშაობს. შესვლით ტელეფონებს შორის სინქრონიზაცია ჩაირთვება; ოფლაინ გაკეთებული ცვლილებები კავშირის აღდგენისას აიტვირთება.
- **ქართული და ინგლისური**, ღია და მუქი თემა, ნაგულისხმევად მოწყობილობის მიხედვით. თანხები და თარიღები ენის შესაბამისად ფორმატდება.

## როგორ მუშაობს

### ფულის ერთი წყარო

ყველა თანხა თეთრების მთელი რიცხვია (1 ლარი = 100 თეთრი). ათწილადი ტექსტი მხოლოდ კიდეებზე არსებობს: შეყვანილი ტექსტი სტრიქონული არითმეტიკით იშლება, ასე რომ „0.29“ ხდება 29 და არა 28.999, გამოტანა კი ენის მიხედვით ფორმატდება. გაყოფის, ბალანსებისა და ანგარიშსწორების ლოგიკა ერთ საზიარო პაკეტშია, რომელსაც ტელეფონიც და სერვერიც უშვებს. ამიტომ სერვერს შეუძლია ტელეფონის გამოგზავნილი შეამოწმოს ხელახლა გამოთვლით, და ყველა ტელეფონი ერთსა და იმავე რიცხვებამდე მიდის.

### გაყოფა და ზედმეტი თეთრი

როცა თანხა თანაბრად არ იყოფა, ზედმეტი თეთრი ვიღაცას უნდა დარჩეს. 100 თეთრი სამზე არის 34, 33, 33. წესი უდიდესი ნაშთისაა: თითოეული იღებს თავისი ზუსტი წილის მთელ ნაწილს, დარჩენილი თეთრები კი სათითაოდ მიდის იმათთან, ვისი წილადი ნაწილიც უდიდესია. თანაბრობისას წევრის იდენტიფიკატორი წყვეტს, ასე რომ შედეგი არ არის დამოკიდებული არც დამატების თანმიმდევრობაზე და არც იმაზე, რომელმა ტელეფონმა ითვალა. წილების ჯამი ყოველთვის ზუსტად თანხის ტოლია და არავინაა თავისი ნამდვილი წილისგან ერთ თეთრზე მეტით დაშორებული.

### ანგარიშსწორება

ჯერ ითვლება თითოეული წევრის წმინდა ბალანსი: დადებითი ნიშნავს, რომ ჯგუფს მართებს მისი, უარყოფითი — რომ მას მართებს ჯგუფის, და ბალანსების ჯამი ყოველთვის ნულია. შემდეგ გეგმა „ხარბია“: თუ ვინმეს ზუსტად იმდენი მართებს, რამდენიც სხვას ერგება, ისინი ერთი გადახდით წყვილდებიან; შემდეგ უდიდესი მოვალე უდიდეს კრედიტორს უხდის, სანამ არაფერი დარჩება. გადახდების რაოდენობა არასდროს აღემატება არანულოვანი ბალანსის მქონე წევრების რაოდენობას მინუს ერთი. აბსოლუტური მინიმუმის პოვნა NP-რთული ამოცანაა, და მეგობრების ჯგუფისთვის ხარბი გეგმა სწორი კომპრომისია.

### ოფლაინ შენახვა და სინქრონიზაცია

ყველა ჩანაწერს აქვს კლიენტზე შექმნილი UUID, `createdAt`, `updatedAt` და `deletedAt`. წაშლა სტრიქონს აღნიშნავს და არა შლის, რომ სხვა ტელეფონებმა გაიგონ, რომ ის აღარ არის. ტელეფონზე ყოველი შეცვლილი სტრიქონი „ჭუჭყიანად“ ინიშნება; ეს ნიშანი არის მთელი ასატვირთი რიგი.

სინქრონიზაცია ერთი მოთხოვნაა თითო ჯგუფზე: ტელეფონი აგზავნის შეცვლილ სტრიქონებს და წინა ჯერზე მიღებულ კურსორს, სერვერი თითოეულ ჩანაწერს საზიარო სქემებით ამოწმებს (გაყოფას ხელახლა ითვლის და წესთან შეუსაბამო წილებს უარყოფს), იყენებს „უფრო ახალი `updatedAt` იგებს“ წესს და აბრუნებს ყველაფერს, რაც კურსორის შემდეგ შეიცვალა. კონფლიქტში წაგებული ჩანაწერი შეცდომა არ არის: ტელეფონი სერვერის ვერსიას იღებს და მასთან თანხვდება. უარყოფილი ჩანაწერები რეპორტდება და ტელეფონზე რიგში რჩება, ქრობის ნაცვლად. ერთი ჯგუფის სინქრონიზაციები სათითაოდ სრულდება PostgreSQL-ის advisory lock-ის ქვეშ, რომ ნელმა ჩამწერმა უკვე წინ წასული კურსორის უკან ვერ ჩაწეროს.

### წევრები და ანგარიშები

ჯგუფის შექმნა ოფლაინ, მხოლოდ სახელებით შეიძლება. როცა ვინმე აპს დააყენებს და მოსაწვევი კოდით შემოუერთდება, ის თავის სახელს ირჩევს და ისაკუთრებს, ასე რომ ამ სახელზე უკვე ჩაწერილი ხარჯები იმ წამიდან მისია. წევრსა და ანგარიშს შორის კავშირს სერვერი ფლობს; ტელეფონებს მისი ატვირთვა არ შეუძლიათ.

### ავტორიზაცია

წვდომის ტოკენები ხანმოკლე ხელმოწერილი JWT-ებია. განახლების ტოკენები შემთხვევითია, მხოლოდ ჰეშის სახით ინახება და ყოველ გამოყენებაზე იცვლება; უკვე გამოყენებულის წარდგენა მთელ იმ სესიას აუქმებს, სხვა მოწყობილობები კი შესული რჩება. პაროლები Node-ის ჩაშენებული scrypt-ით იჰეშება. შესვლა უცნობ ელფოსტაზეც და არასწორ პაროლზეც ერთნაირად პასუხობს და ჰეშს ორივე შემთხვევაში ითვლის, ასე რომ დრო ვერაფერს ამხელს. ავტორიზაციის ენდპოინტები კლიენტის მისამართის მიხედვით ლიმიტირებულია.

### ქართული გრამატიკით

„Nino pays Luka“ არის „ნინო უხდის ლუკას“: სახელი ფორმას იცვლის. თარგმანის ფენა სახელებს მიცემითსა და მოთხრობით ბრუნვაში აყენებს და ლათინური სახელებს ისე წერს, როგორც ქართულში არის მიღებული: „Luka-ს“. ტესტი ამოწმებს, რომ ყველა სტრიქონი ორივე ენაზე არსებობს ერთნაირი ჩასამატებელი ველებით.

## როგორ გავუშვათ

წინაპირობები: Node 22 ან უფრო ახალი, Docker და Expo Go ტელეფონზე (ან სიმულატორი).

```sh
npm install                      # ყველა workspace-ს აყენებს და Prisma კლიენტს აგენერირებს
```

სერვერი:

```sh
cp server/.env.example server/.env   # JWT_SECRET დააყენე ნებისმიერ 32+ სიმბოლოიან სტრიქონზე
npm run db:up -w server              # PostgreSQL Docker-ში
npm run db:deploy -w server          # მიგრაციების გაშვება
npm run dev -w server                # http://localhost:4000
```

აპი:

```sh
cp app/.env.example app/.env         # EXPO_PUBLIC_API_URL დააყენე კომპიუტერის ლოკალური ქსელის მისამართზე, მაგ. http://192.168.1.20:4000
npm run start -w app                 # QR კოდი Expo Go-თი დაასკანირე
```

ტელეფონი და კომპიუტერი ერთ Wi-Fi-ზე უნდა იყოს, Windows Firewall-მა კი 4000 პორტზე შემომავალი კავშირები უნდა დაუშვას. აპი სერვერის გარეშე ყველაფერს ლოკალურად აკეთებს; შესვლა სინქრონიზაციასა და მოსაწვევ კოდებს რთავს.

### Development build

აპის საცდელად Expo Go საკმარისია, მაგრამ ის ზოგადი გარსია. Development build Tsili-ის საკუთარი ნატიური გარსია, ზუსტად მისი მოდულებით, და სწორედ მისგან კეთდება რელიზიც. Android SDK-ით, JDK-ით და მიერთებული მოწყობილობით ან ემულატორით:

```sh
npm run android:dev -w app       # ნატიურ პროექტს აკომპილირებს და აყენებს; შემდეგ Metro ჩვეულებრივ გაუშვი
```

გენერირებული `android/` საქაღალდე ბილდის არტეფაქტია და რეპოში არ ინახება. ლოკალური SDK-ის გარეშე იგივე ბილდი Expo-ს ღრუბელში კეთდება: `npx eas-cli build --profile development --platform android` `app/`-დან, `app/eas.json`-ის პროფილებით.

ტესტები და შემოწმებები:

```sh
npm test                      # shared, server (Docker-ის ბაზა სჭირდება), app
npm run typecheck
npm run bundle:check -w app   # Metro ბანდლი Android-ისთვის; იმპორტისა და კონფიგურაციის შეცდომებს მოწყობილობის გარეშე იჭერს
```

## მდგომარეობა

ზემოთ აღწერილი ყველაფერი განხორციელებული და ტესტირებულია, CI კი ყოველ push-ზე ამოწმებს. შემდეგი ნაბიჯები: ნატიური თარიღის ამრჩევი და სინქრონიზაციის გვერდებად დაყოფა ძალიან დიდი ჯგუფებისთვის.
